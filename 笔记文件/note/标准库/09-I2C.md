# I²C：把地址、方向与 ACK 放回完整时序

> I²C 规定总线寻址与字节传送，设备再规定寄存器与命令。本文用 I2C2 访问 MPU6050，区分总线上的时序和 STM32F1 软件必须完成的操作。

## 1. 两根线怎样传数据

SCL 是时钟线，SDA 是双向数据线。普通 I²C 接口采用开漏结构：输出低电平时主动拉低，输出高电平时释放线路，由外部上拉电阻拉高。SCL 和 SDA 都需要合适的上拉。

```text
上拉电源 ─ 电阻 ─ SCL ─ 主机与各从机的 SCL
上拉电源 ─ 电阻 ─ SDA ─ 主机与各从机的 SDA
```

普通数据位在 SCL 高期间保持稳定，在 SCL 低期间准备下一位。START 和 STOP 是专门的例外：

| 符号 | SDA 的变化 | 此时 SCL | 含义 |
| --- | --- | --- | --- |
| S | 高→低 | 高 | START，开始事务 |
| Sr | 高→低 | 高 | 重复 START，继续占用总线并开始新的寻址阶段 |
| P | 低→高 | 高 | STOP，结束事务并释放总线 |

每字节高位先发，占 8 个时钟，随后第 9 个时钟用于 ACK/NACK。数据发送方在第 9 位释放 SDA，由**本字节的接收方**决定应答：拉低为 ACK，保持释放为 NACK。

所以 ACK 不是永远由从机发：主机读数据时，主机是接收方，也要产生 ACK/NACK。基本规则见 [NXP UM10204](https://www.nxp.com/docs/en/user-guide/UM10204.pdf)。

## 2. 7 位地址、线上地址字节、寄存器地址

以 AD0 为低的 MPU6050 为例：

| 名称 | 数值 | 作用 |
| --- | --- | --- |
| 7 位设备地址 | `0x68` | 选择哪一个设备 |
| 写方向的线上地址字节 | `(0x68 << 1) | 0 = 0xD0` | 7 位设备地址加写方向 |
| 读方向的线上地址字节 | `(0x68 << 1) | 1 = 0xD1` | 同一设备，改成读方向 |
| WHO_AM_I 寄存器地址 | `0x75` | 选择设备内部的哪个寄存器 |

AD0 为高时，7 位地址变为 `0x69`。不要把 `0xD0` 与 `0xD1` 当成两个设备，也不要把 `0x75` 当成总线设备地址。

本笔记接口统一接收 `addr7`，调用标准库 `I2C_Send7bitAddress()` 时才左移一次。已核对本地 ST 标准库实现：该函数只设置/清除最低方向位，不会替你把 `0x68` 左移。

## 3. 一次写寄存器和一次读寄存器

### 3.1 写入一个寄存器

例如向 `PWR_MGMT_1 (0x6B)` 写入 `0x01`：

```text
主机： S | D0 |     | 6B |     | 01 |     | P
从机：        ACK        ACK        ACK
含义：     地址+写   寄存器地址   写入的数据
```

设备地址后、寄存器地址后、数据后都有第 9 位应答。任一阶段收到意外 NACK，都不能直接继续假定写入成功。

### 3.2 读一个寄存器，为什么先写后读

读 WHO_AM_I：

```text
S | D0 | ACK | 75 | ACK | Sr | D1 | ACK | 68 | NACK | P
    主机发     主机发          主机发      从机发   主机发
    地址+写    寄存器地址       地址+读     数据     结束读取
```

前半段“写”只是在设置设备内部的读取位置，没有把业务数据写进该寄存器。重复 START 后重新寻址，把方向改为读。

从机返回最后一个数据字节后，主机发 NACK 表示“这一轮不继续读了”，然后 STOP。这个 NACK 是正常结束动作，不等于通信失败。

连续读取 N 个字节时，主机通常对前 N−1 个字节 ACK，对最后一个字节 NACK；设备是否自动增加寄存器地址、能连续读多长，由设备协议决定。

## 4. 总线时序怎样对应到 STM32F1 标志

| 总线/外设阶段 | 观察什么 | 随后做什么 |
| --- | --- | --- |
| 产生 START | `SB=1` | 发设备地址字节 |
| 地址得到 ACK | `ADDR=1` | 完成 SR1→SR2 序列，进入数据阶段 |
| 发送 DR 可写 | `TXE=1` | 可继续写数据，但前一字节不一定已完全发出 |
| 发送字节完成 | `BTF=1` | 适合在最后字节后安排 STOP 或重复 START |
| 接收 DR 有数据 | `RXNE=1` | 按接收字节数对应的流程读 DR |
| 未得到期望 ACK | `AF=1` | 停止当前事务并报告失败 |

`I2C_CheckEvent()` 会依次读 SR1、SR2，因而可能顺带清掉 ADDR。对普通发送流程这符合事件处理；对 F1 **只读 1 字节**的接收流程，清 ADDR 前必须先关闭 ACK，不能直接用一个通用“等接收模式选中”函数把这个顺序隐藏掉。

单字节接收的关键顺序是：

```text
等待 ADDR（先只读 SR1）
    → ACK=0
    → 读 SR1、SR2 清 ADDR
    → 安排 STOP
    → 等 RXNE，读唯一一个数据字节
    → 等 STOP 完成，再恢复 ACK
```

清 ADDR 到安排 STOP 之间使用短临界区，避免中断打断关键时序。F1 的 1 字节、2 字节和更多字节接收结束序列不同，不能简单循环单字节收尾代码。这个顺序依据 [ST AN2824，单字节接收说明与流程图](https://www.st.com/resource/en/application_note/an2824-stm32f10xxx-ic-optimized-examples-stmicroelectronics.pdf)。

## 5. 标准库单寄存器读写示例

使用 I2C2 默认引脚 PB10=SCL、PB11=SDA，外接上拉。示例限定一个调用者、主机轮询模式，无同时操作该外设的中断/DMA。等待返回 0 表示失败，调用者不得把输出数据当成有效值。

### 5.1 初始化和等待工具

```c
#include "stm32f10x.h"

void BusI2C_Init(void)
{
    GPIO_InitTypeDef gpio;
    I2C_InitTypeDef bus;
    RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOB, ENABLE);
    RCC_APB1PeriphClockCmd(RCC_APB1Periph_I2C2, ENABLE);
    GPIO_StructInit(&gpio);
    gpio.GPIO_Pin = GPIO_Pin_10 | GPIO_Pin_11;
    gpio.GPIO_Mode = GPIO_Mode_AF_OD;
    gpio.GPIO_Speed = GPIO_Speed_50MHz;
    GPIO_Init(GPIOB, &gpio);
    I2C_StructInit(&bus);
    bus.I2C_Mode = I2C_Mode_I2C;
    bus.I2C_ClockSpeed = 100000;
    bus.I2C_DutyCycle = I2C_DutyCycle_2;
    bus.I2C_Ack = I2C_Ack_Enable;
    bus.I2C_AcknowledgedAddress = I2C_AcknowledgedAddress_7bit;
    bus.I2C_OwnAddress1 = 0;
    I2C_Init(I2C2, &bus);
    I2C_Cmd(I2C2, ENABLE);
}

static int I2C_WaitSR1(uint16_t mask)
{
    uint32_t budget = 100000U;
    while (budget-- != 0U) {
        uint16_t sr = (uint16_t)I2C2->SR1; // 不读 SR2，保留 ADDR
        if (sr & (I2C_SR1_AF | I2C_SR1_BERR |
                  I2C_SR1_ARLO | I2C_SR1_OVR)) return 0;
        if ((sr & mask) == mask) return 1;
    }
    return 0;
}

static void I2C_ClearADDR(void)
{
    volatile uint16_t dummy = (uint16_t)I2C2->SR1;
    dummy = (uint16_t)I2C2->SR2;
    (void)dummy;
}

static int I2C_Begin(void)
{
    uint32_t budget = 100000U;
    while ((I2C2->SR2 & I2C_SR2_BUSY) != 0U)
        if (--budget == 0U) return 0;
    I2C_NACKPositionConfig(I2C2, I2C_NACKPosition_Current);
    I2C_AcknowledgeConfig(I2C2, ENABLE);
    return 1;
}

static int I2C_Address(uint8_t addr7, uint8_t direction)
{
    I2C_GenerateSTART(I2C2, ENABLE);
    if (!I2C_WaitSR1(I2C_SR1_SB)) return 0;
    I2C_Send7bitAddress(I2C2, (uint8_t)(addr7 << 1), direction);
    return I2C_WaitSR1(I2C_SR1_ADDR); // 留给调用者按方向处理 ADDR
}

static int I2C_WaitStop(void)
{
    uint32_t budget = 100000U;
    while ((I2C2->CR1 & I2C_CR1_STOP) != 0U)
        if (--budget == 0U) return 0;
    return 1;
}

static void I2C_Abort(void)
{
    uint16_t sr1 = (uint16_t)I2C2->SR1;
    if (!(sr1 & I2C_SR1_ARLO) && (I2C2->SR2 & I2C_SR2_MSL))
        I2C_GenerateSTOP(I2C2, ENABLE);
    // 仅尽力停止。上层记录错误并完成清错/恢复后，才能发起新事务。
}
```

预算仍是循环次数，不是毫秒。超时、总线错误和仲裁丢失在此均返回失败；生产驱动应区分错误原因、采用计时超时，并实现恢复流程。`I2C_Abort()` 不保证卡住的总线已经释放，不应失败后无限盲重试。

### 5.2 写一个字节

```c
int I2C_WriteReg8(uint8_t addr7, uint8_t reg, uint8_t value)
{
    if (addr7 > 0x7FU || !I2C_Begin()) return 0;
    if (!I2C_Address(addr7, I2C_Direction_Transmitter)) goto fail;
    I2C_ClearADDR();
    I2C_SendData(I2C2, reg);
    if (!I2C_WaitSR1(I2C_SR1_BTF)) goto fail;
    I2C_SendData(I2C2, value);
    if (!I2C_WaitSR1(I2C_SR1_BTF)) goto fail;
    I2C_GenerateSTOP(I2C2, ENABLE);
    if (!I2C_WaitStop()) goto fail;
    return 1;
fail:
    I2C_Abort();
    return 0;
}
```

### 5.3 读一个字节

```c
int I2C_ReadReg8(uint8_t addr7, uint8_t reg, uint8_t *out)
{
    uint32_t saved;
    uint8_t value;
    if (addr7 > 0x7FU || out == 0 || !I2C_Begin()) return 0;

    // 先设置寄存器指针。
    if (!I2C_Address(addr7, I2C_Direction_Transmitter)) goto fail;
    I2C_ClearADDR();
    I2C_SendData(I2C2, reg);
    if (!I2C_WaitSR1(I2C_SR1_BTF)) goto fail;

    // 没有 STOP，直接重复 START，改为读方向。
    if (!I2C_Address(addr7, I2C_Direction_Receiver)) goto fail;
    saved = __get_PRIMASK();
    __disable_irq();
    I2C_AcknowledgeConfig(I2C2, DISABLE);
    I2C_ClearADDR();
    I2C_GenerateSTOP(I2C2, ENABLE);
    __set_PRIMASK(saved); // 恢复原中断状态，而非无条件开中断

    if (!I2C_WaitSR1(I2C_SR1_RXNE)) goto fail;
    value = (uint8_t)I2C_ReceiveData(I2C2);
    if (!I2C_WaitStop()) goto fail;
    I2C_AcknowledgeConfig(I2C2, ENABLE);
    *out = value;
    return 1;
fail:
    I2C_Abort();
    return 0;
}
```

输出值只在成功后写入，因此能够区分“读到 0”和“读取失败”。这里只处理单字节读，不应将它直接改成 N 字节循环而保留同一收尾序列。

## 6. MPU6050 寄存器和数据编码

先读 `0x75` 的 WHO_AM_I 验证设备。该寄存器通常为 `0x68`，AD0 改变总线地址不会把 WHO_AM_I 变成 `0x69`。再按应用要求写配置，且检查每次写入的返回值。

| 寄存器 | 原笔记示例值 | 解释 |
| --- | --- | --- |
| `0x6B PWR_MGMT_1` | `01` | 退出睡眠，选择 X 轴陀螺仪相关时钟源 |
| `0x6C PWR_MGMT_2` | `00` | 各轴不设为待机 |
| `0x1A CONFIG` | `06` | 选择 DLPF 配置 6，不应只写“滤波最高” |
| `0x19 SMPLRT_DIV` | `09` | 在此滤波配置的 1 kHz 输出率下，分频到 100 Hz |
| `0x1B GYRO_CONFIG` | `18` | 陀螺仪量程 ±2000 °/s |
| `0x1C ACCEL_CONFIG` | `18` | 加速度计量程 ±16 g |

初始化还需遵守上电/复位后的等待要求。传感器输出的高低字节要按寄存器定义拼接成有符号量，再按量程换算；多轴采样应采用设备支持的连续读取机制，避免逐寄存器事务跨过采样更新边界。寄存器定义见 [TDK InvenSense MPU6050 寄存器手册](https://invensense.tdk.com/wp-content/uploads/2015/02/MPU-6000-Register-Map1.pdf)。

## 7. HAL 对照与排查

STM32F1 HAL 的 `HAL_I2C_Mem_Read/Write()` 可以封装此类“设备地址 + 寄存器地址”的事务。`DevAddress` 仍按该 HAL 接口要求传 `addr7 << 1`；`I2C_MEMADD_SIZE_8BIT` 表示寄存器地址宽度，不是设备地址宽度。必须检查返回状态，再使用数据。

| 现象 | 优先检查 |
| --- | --- |
| 地址阶段没有 ACK | 地址是否重复左移、AD0、电源、上拉、引脚 |
| 只读一字节时多读/卡住 | ACK、ADDR、STOP 的操作先后 |
| 总线一直 BUSY | SDA/SCL 是否被拉住、上次事务是否中止、芯片勘误与恢复流程 |
| 数据能读但数值不对 | 寄存器、量程、符号、高低字节、采样配置 |

软件 I²C 可以更直接控制时序，但仍需满足开漏、应答、时钟拉伸和超时规则；硬件 I²C 也不能笼统称为“不稳定”。应按具体 STM32 型号和修订版检查勘误。
