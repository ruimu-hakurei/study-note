# 指针与 C 内存模型

> 指针不是“神秘箭头”，而是一个保存地址值的对象。读指针代码时始终分清三件事：**指针自己在哪里、它保存了谁的地址、那个目标对象还活着吗**。

---

## 一、指针自己也是变量

### 1. 一个最小例子

```c
int number = 42;
int *pointer = &number;
```

假设使用符号地址观察内存：

```text
自动存储区域（示意）

地址 A100                         地址 A200
┌──────────────────┐             ┌──────────────────┐
│ number           │             │ pointer          │
│ int 值：42       │ <────────── │ int * 值：A100   │
└──────────────────┘             └──────────────────┘
       ▲                                  ▲
       │                                  │
   &number == A100                    &pointer == A200

pointer  == A100
*pointer == 42
```

| 表达式 | 含义 | 类型 |
|---|---|---|
| `number` | `number` 中保存的整数 | `int` |
| `&number` | `number` 的地址 | `int *` |
| `pointer` | `pointer` 中保存的地址 | `int *` |
| `*pointer` | 沿地址找到目标对象 | `int` 左值 |
| `&pointer` | 指针对象自身的地址 | `int **` |

```c
*pointer = 99;       // 通过 pointer 修改它所指向的 number
printf("%d\n", number);  // 99
```

> ✅ `pointer` 是地址值，`*pointer` 是这个地址所指向的对象，`&pointer` 则是指针变量自己的地址。

### 2. 声明中的 `*` 与表达式中的 `*`

```c
int object = 7;
int *pointer = &object; // 声明：pointer 的类型是 int *
int value = *pointer;   // 表达式：解引用 pointer
```

声明要从变量名向外读：

```c
int *p, value;
```

这里只有 `p` 是指针，`value` 仍是 `int`。为了避免误读，复杂声明尽量一行一个变量。

---

## 二、指针类型到底决定什么

指针的类型主要告诉编译器两件事：

1. 解引用时，把目标当作什么类型的对象访问。
2. 做指针加减时，每一步跨过多大的元素。

```c
int values[3] = {10, 20, 30};
int *p = values;

p + 1;       // 指向 values[1]，跨过 sizeof(int) 字节
*(p + 2);    // 访问 values[2]
```

> ⚠️ 不要把 `int * + 1` 永远记成“加 4 字节”。它跨过的是 `sizeof(int)`；`int` 的实际大小由实现决定。

指针对象本身占多大空间，要通过 `sizeof` 查询：

```c
printf("%zu\n", sizeof(int *));
printf("%zu\n", sizeof(char *));
```

常见 32 位 ABI 的数据指针是 4 字节，常见 64 位 ABI 是 8 字节，但 C 标准不保证“所有平台、所有种类的指针都服从这两个数字”，也不应根据指针大小推断目标对象大小。

### 指针没有自动携带的信息

一个普通指针值通常不记录：

- 目标数组有多少个元素。
- 目标对象是否已经离开生命周期。
- 这块内存由谁负责释放。
- 还能安全访问多少字节。

这些信息需要程序通过长度变量、API 契约和所有权规则另外维护。

## 三、比“内存四区”更可靠的对象模型

### 1. 对象、地址与生命周期

C 程序操作的是对象。一个对象具有：

- 类型：决定大小、对齐和如何解释其中的位。
- 存储位置：可以通过合法指针访问。
- 生命周期：只有生命周期内才能访问。
- 值：可能尚未初始化，也可能已经被程序写入。

原笔记使用“代码区、常量区、全局区、栈区、堆区”来解释内存。那是常见操作系统上的典型布局，不是 C 标准强制规定的固定地图。标准层面更关注存储期：

| 存储期 | 常见对象 | 何时开始 | 何时结束 |
|---|---|---|---|
| 自动存储期 | 普通局部变量、形参 | 执行进入相应块或函数 | 离开相应块或函数 |
| 静态存储期 | 全局变量、`static` 对象、字符串字面量 | 程序开始 | 程序结束 |
| 动态分配存储 | `malloc/calloc/realloc` 得到的区域 | 分配成功 | `free` 或成功的 `realloc` 结束旧区域 |
| 线程存储期 | `_Thread_local` 对象 | 线程开始 | 线程结束 |

常见桌面实现可能呈现为：

```text
较高地址
┌──────────────────────────────────────────┐
│ 调用栈：局部变量 number、pointer          │  自动存储期
├──────────────────────────────────────────┤
│                  ...                     │
├──────────────────────────────────────────┤
│ 动态分配区域：malloc 返回的字节块         │  直到 free
├──────────────────────────────────────────┤
│ 静态/全局数据：global、static             │  静态存储期
├──────────────────────────────────────────┤
│ 字符串字面量等实现常放置的只读数据         │  静态存储期
├──────────────────────────────────────────┤
│ 程序指令                                 │
└──────────────────────────────────────────┘
较低地址

图中顺序、增长方向和区域名称都由具体平台决定。
```

### 2. 指针和目标可以拥有不同生命周期

```c
int *data = malloc(10 * sizeof *data);
```

在典型实现里：

- 局部指针变量 `data` 自己常在调用栈上。
- 它指向的动态区域常被称为“堆内存”。
- 离开当前块时，`data` 这个指针变量会消失。
- 动态区域不会因此自动释放；若没有保存地址并 `free`，就泄漏了。

反过来，`free(data)` 后局部变量 `data` 可能仍保存旧地址数值，但目标对象的生命周期已经结束，这时它是悬空指针。

作用域与生命周期的详细区别见 [[04-函数、作用域与生命周期]]。

## 四、什么时候才允许解引用

执行 `*p` 前，至少要确认：

1. `p` 不是空指针。
2. `p` 已初始化为一个合法地址。
3. 目标对象仍在生命周期内。
4. 地址满足目标类型的对齐要求。
5. 目标对象的实际类型允许通过这个指针类型访问。
6. 访问没有越过数组边界。

### 1. 空指针

```c
int *p = NULL;

if (p != NULL) {
    printf("%d\n", *p);
}
```

`NULL` 表示“不指向任何对象”的空指针值。解引用空指针是未定义行为，不应把“必定段错误”当成语言保证。

### 2. 未初始化指针，也叫野指针

```c
int *p;
// *p = 100;    // 未定义行为：p 的值不确定
```

暂时没有目标时，先初始化为 `NULL`。

### 3. 悬空指针

```c
int *p = malloc(sizeof *p);
if (p != NULL) {
    *p = 42;
    free(p);
    p = NULL;        // 避免以后误用 p 这个名字
}
```

把 `p` 置空只修复了这一个变量，其他保存过同一地址的别名仍然悬空：

```text
free 前：
p ─────┐
       ├────> [ 动态 int 对象 ]
alias ─┘

free 后：
p = NULL
alias ───────> [ 生命周期已结束的旧区域 ]  ← 仍然悬空
```

## 五、指针运算只能在数组边界内解释

```c
int values[4] = {10, 20, 30, 40};
int *begin = values;
int *end = values + 4;   // 可以形成尾后一位指针

for (int *p = begin; p != end; ++p) {
    printf("%d\n", *p);
}
```

合法模型是：

```text
begin
  │
  ▼
┌────┬────┬────┬────┐
│ 10 │ 20 │ 30 │ 40 │
└────┴────┴────┴────┘
                       ▲
                       │
                      end
```

- 可以形成并比较尾后一位指针 `end`。
- 不能解引用 `end`。
- `p + n` 必须仍落在同一数组或它的尾后一位。
- 两个指针只有指向同一数组对象时，指针相减才有“相隔多少元素”的含义。

```c
#include <stddef.h>
#include <stdio.h>

ptrdiff_t distance = end - begin;
printf("%td\n", distance);  // 4
```

不要对两个无关对象的指针做减法或依赖大小比较。`void *` 没有目标元素大小，标准 C 不允许直接对 `void *` 做加减；某些编译器把它当扩展。

## 六、`const` 与指针

从变量名开始读，先看它紧挨着谁：

| 声明 | 指针能改指向吗 | 能通过它改目标吗 |
|---|---:|---:|
| `const int *p` | 可以 | 不可以 |
| `int const *p` | 可以 | 不可以，与上一行相同 |
| `int *const p` | 不可以 | 可以 |
| `const int *const p` | 不可以 | 不可以 |

```c
int first = 10;
int second = 20;

const int *view = &first;
view = &second;          // 合法：view 可以换目标
// *view = 30;           // 错：不能通过 view 修改目标

int *const fixed = &first;
*fixed = 30;            // 合法：目标可修改
// fixed = &second;      // 错：fixed 自己不能改地址值
```

> ⚠️ “`const` 在左边就是内容不能改，在右边就是指针不能改”只适合简单声明。更稳妥的方法是从变量名向外读：`fixed` 先遇到 `const`，所以 fixed 自己固定；`view` 先遇到 `*`，再看到左边的 `const int`，所以它指向只读视图。

`const` 限制的是通过当前表达式进行修改的能力，不等于目标对象必定位于物理只读内存。

## 七、C 只有值传递，指针值也会被复制

原笔记把两种函数调用称为“值传递”和“地址传递”。更准确地说：**C 的函数参数永远按值传递**。区别只在于复制的是普通整数，还是一个地址值。

### 1. 传普通整数

```c
static void wrong_swap(int left, int right)
{
    int temporary = left;
    left = right;
    right = temporary;
}
```

`left` 和 `right` 是实参值的副本，交换副本不会修改调用者。

### 2. 传指针值

```c
#include <stdio.h>

static void swap_ints(int *left, int *right)
{
    if (left == NULL || right == NULL) {
        return;
    }

    int temporary = *left;
    *left = *right;
    *right = temporary;
}

int main(void)
{
    int a = 1;
    int b = 2;

    swap_ints(&a, &b);
    printf("a=%d, b=%d\n", a, b);
    return 0;
}
```

调用时仍然复制了两个指针值，但这些副本都指向调用者的对象，所以函数可以沿地址修改原对象。

```text
main 中                         swap_ints 中
a [1] <────────────────────── left [ &a 的副本 ]
b [2] <────────────────────── right[ &b 的副本 ]
```

> ✅ 想修改调用者的 `int`，传 `int *`；想修改调用者的 `int *`，就要传该指针对象的地址，即 `int **`。后者见 [[07-指针数组、数组指针与多级指针]]。

## 八、动态内存与所有权

### 1. `malloc`、`calloc`、`realloc`、`free`

```c
#include <stdlib.h>

size_t count = 10;
int *values = malloc(count * sizeof *values);

if (values == NULL) {
    /* 分配失败 */
}

free(values);
values = NULL;
```

几个基本规则：

- `malloc` 返回满足普通对象对齐要求的动态区域，初始字节值不确定。
- `calloc` 分配并把所有字节清零；它不是“调用构造函数”。
- `realloc` 可能原地扩大，也可能搬到新地址。
- `free` 只能接收空指针，或当前仍由动态分配函数返回且尚未释放的分配块起始地址。
- 在 C 中 `void *` 可以隐式转换为对象指针，不必强制转换 `malloc` 的返回值。

> ⚠️ 不要释放局部变量地址、字符串字面量地址、数组内部地址，也不要重复释放同一分配。

### 2. 用 `sizeof *pointer` 写分配公式

```c
int *values = malloc(count * sizeof *values);
```

它比 `sizeof(int)` 更容易在修改类型后保持正确。不过还要防止乘法溢出：

```c
#include <stdint.h>

if (count > SIZE_MAX / sizeof *values) {
    /* count * sizeof *values 无法由 size_t 表示 */
}
```

### 3. 所有权

“有一个指针指向内存”不等于“这个指针拥有内存”。可以把指针角色分成：

| 角色 | 可以读写目标吗 | 负责 `free` 吗 |
|---|---:|---:|
| 拥有者 | 由接口约定 | 是，且恰好一次 |
| 可写借用 | 是 | 否 |
| 只读借用 | 只读 | 否 |

一个可靠函数应写明：

- 输入指针是否只是借用。
- 函数是否接管输入对象。
- 返回的动态对象由谁释放。
- 失败时原对象是否保持不变。

### 4. `realloc` 必须先接到临时指针

错误写法：

```c
values = realloc(values, new_count * sizeof *values);
```

如果 `realloc` 失败，它返回 `NULL`，原分配仍然有效，但原地址已被覆盖，造成泄漏。

正确写法：

```c
int *new_values = realloc(values, new_count * sizeof *values);
if (new_values != NULL) {
    values = new_values;
}
```

> ⚠️ `realloc` 成功后，旧分配的生命周期已经结束。即使返回的数值地址恰好相同，也不要继续使用之前保存的内部指针或别名；应从新返回值重新建立它们。

## 九、完整示例：可增长整数数组

下面的 `append_int` 通过 `int **` 更新调用者的指针，并保证分配失败时原数组仍然有效。

```c
#include <stdbool.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>

/*
 * 所有权：
 * - *data 始终由调用者拥有，最终由调用者 free。
 * - 函数可能用 realloc 替换 *data 指向的分配。
 *
 * 失败路径：
 * - 返回 false 时，*data、*length、*capacity 保持原值。
 */
static bool append_int(int **data, size_t *length, size_t *capacity,
                       int value)
{
    if (data == NULL || length == NULL || capacity == NULL) {
        return false;
    }

    /* 边界：拒绝已经被破坏的三元组状态。 */
    if (*length > *capacity || (*capacity != 0 && *data == NULL)) {
        return false;
    }

    if (*length == *capacity) {
        size_t new_capacity;

        if (*capacity == 0) {
            new_capacity = 4;
        } else {
            if (*capacity > SIZE_MAX / 2) {
                return false;
            }
            new_capacity = *capacity * 2;
        }

        if (new_capacity > SIZE_MAX / sizeof **data) {
            return false;
        }

        /*
         * 难点：
         * data 的类型是 int **；
         * *data 是调用者的 int *；
         * **data 是一个 int，所以 sizeof **data 正是单个元素大小。
         */
        int *new_data = realloc(*data, new_capacity * sizeof **data);
        if (new_data == NULL) {
            return false;  // realloc 失败时，旧的 *data 仍然有效
        }

        /*
         * 只有分配成功后才提交新状态。
         * 这样调用者不会看见“指针已换、容量没换”的半完成状态。
         */
        *data = new_data;
        *capacity = new_capacity;
    }

    (*data)[*length] = value;
    ++*length;
    return true;
}

int main(void)
{
    int *numbers = NULL;
    size_t length = 0;
    size_t capacity = 0;

    for (int value = 10; value <= 100; value += 10) {
        if (!append_int(&numbers, &length, &capacity, value)) {
            fputs("追加失败\n", stderr);
            free(numbers);
            return 1;
        }
    }

    for (size_t i = 0; i < length; ++i) {
        printf("%d%s", numbers[i], i + 1 == length ? "\n" : " ");
    }

    free(numbers);   // 所有权：main 释放最终分配
    numbers = NULL;
    return 0;
}
```

关键内存关系：

```text
append_int 调用前

main 的 numbers 指针槽
┌────────────────┐
│  动态块地址 H0 │ ─────> [10][20][30][空]
└────────────────┘
        ▲
        │
data ───┘    data == &numbers

realloc 成功并搬迁后

main 的 numbers 指针槽
┌────────────────┐
│  新块地址 H1   │ ─────> [10][20][30][40][空][空][空][空]
└────────────────┘

旧块 H0 的生命周期已经结束。
```

## 十、返回地址时要检查目标生命周期

错误示例：

```c
char *make_text_wrong(void)
{
    char text[] = "hello";
    return text;          // 返回后 text 已不存在
}
```

可选设计：

1. 让调用者传入缓冲区和容量。
2. 返回动态分配对象，并明确调用者负责 `free`。
3. 返回静态存储期对象的只读视图，但要说明它会被后续调用覆盖还是固定不变。

```c
static bool write_greeting(char output[], size_t capacity)
{
    static const char greeting[] = "hello";

    if (capacity < sizeof greeting) {
        return false;
    }

    for (size_t i = 0; i < sizeof greeting; ++i) {
        output[i] = greeting[i];
    }
    return true;
}
```

## 十一、`void *` 与对象表示

`void *` 可以保存任意对象指针转换后的值，再转换回原对象指针类型：

```c
int value = 42;
void *generic = &value;
int *again = generic;
```

但 `void` 没有大小，不能直接解引用 `void *`，标准 C 也不能对它做指针算术。

如果只是观察对象的原始字节，可以使用 `unsigned char *`：

```c
const unsigned char *bytes = (const unsigned char *)&value;

for (size_t i = 0; i < sizeof value; ++i) {
    printf("%02X ", (unsigned)bytes[i]);
}
```

这能查看对象表示，但不要据此假设所有机器的字节序、整数表示和对齐方式相同。相关内容见 [[01-数制、字符与数据表示]]。

## 十二、常见错误清单

| 错误 | 后果或修正 |
|---|---|
| 未初始化就解引用 | 未定义行为；先指向合法对象或设为 `NULL` |
| 解引用 `NULL` | 未定义行为 |
| `free` 后继续访问 | use-after-free |
| 重复 `free` | 未定义行为 |
| 释放数组内部地址 | 必须释放分配函数返回的起始地址 |
| 忘记 `free` | 内存泄漏 |
| 用 `sizeof(pointer)` 当目标大小 | 分配对象时优先写 `sizeof *pointer` |
| 直接覆盖 `realloc` 原指针 | 失败时泄漏；先用临时指针 |
| 认为置空一个指针会修复所有别名 | 其他别名仍可能悬空 |
| 对无关对象做指针减法 | 没有合法的数组内距离含义 |
| 解引用尾后一位指针 | 尾后一位只能形成和比较，不能访问 |
| 用 `%d` 打印指针或 `size_t` | 指针用 `%p` 和 `(void *)`；`size_t` 用 `%zu` |
| 认为“常量都不能取地址” | `&` 需要可取地址的对象或函数；关键不在“常量”二字 |

---

## 十三、一句话总结

> ✅ 指针变量保存地址，但不会自动保存长度、生命周期或所有权。

> ✅ C 始终按值传参；传指针只是把地址值复制给函数，让函数能沿地址访问调用者对象。

> ✅ 动态内存的正确性依赖一条清晰规则：谁拥有、何时释放、失败时是否保持原状态。
