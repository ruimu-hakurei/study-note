# 未定义行为、调试与自测

> C 最危险的错误不是“语法错”，而是程序已经越界、悬空或违反类型规则，编译器却仍允许它生成可执行文件。

---

## 一、先分清三种结果

| 类别 | 含义 | 例子 |
|---|---|---|
| 定义良好 | C 标准明确规定结果 | 无符号整数按模数回绕 |
| 实现定义 / 未指定 | 实现必须说明，或允许在若干结果中选择 | 普通 `char` 是否有符号、函数实参求值顺序 |
| 未定义行为（UB） | 标准不再约束程序会发生什么 | 数组越界、释放后访问、修改字符串字面量 |

> ⚠️ 未定义行为不等于“必然崩溃”。它可能打印正确结果、偶尔出错、换优化等级后出错，甚至让编译器删除你以为必会执行的代码。

## 二、原笔记中几个需要更精确的说法

| 容易记成的绝对说法 | 更准确的理解 |
|---|---|
| 1 字节永远是 8 位 | C 只保证 1 字节等于 `CHAR_BIT` 位且 `CHAR_BIT >= 8`；现代通用平台通常为 8 |
| 普通 `char` 就是 `signed char` | 普通 `char`、`signed char`、`unsigned char` 是三种类型；普通 `char` 是否有符号由实现决定 |
| 有符号数超范围会循环 | 无符号整数按模数回绕；有符号整数运算溢出通常是未定义行为 |
| 所有指针在 32/64 位系统都分别为 4/8 字节 | 这是常见 ABI 的情况，不是 C 对所有平台的保证；应以 `sizeof pointer` 为准 |
| 字符串字面量一定在“只读常量区” | C 只保证修改字符串字面量是未定义行为；具体放在哪个段是实现细节 |
| `sizeof` 永远在编译期计算 | 对普通类型/对象通常如此，但变长数组 VLA 的 `sizeof` 可能在运行期求值 |
| 栈固定 8 MB | 栈大小取决于操作系统、链接参数、线程配置和嵌入式链接脚本，不是语言规则 |
| 二维数组就是二级指针 | 真二维数组是连续的“数组的数组”；`int **` 通常指向一个指针表，布局不同 |

这些修正不会让入门更难，反而能防止后面遇到平台差异时推理崩掉。

## 三、最高频的未定义行为

### 1. 数组越界

```c
int values[3] = {10, 20, 30};
values[3] = 40;       // ❌ 合法下标只有 0、1、2
```

C 不做边界检查。越界写入可能污染邻近变量、返回地址或分配器元数据。

### 2. 使用未初始化值

```c
int count;
if (count > 0) {      // ❌ 自动变量 count 的值不确定
    /* ... */
}
```

### 3. 解引用空指针或野指针

```c
int *p = NULL;
*p = 1;               // ❌ NULL 不指向 int 对象

int *q;                // q 未初始化
*q = 2;               // ❌ q 保存的是不确定地址
```

### 4. 释放后继续访问

```c
int *data = malloc(4 * sizeof *data);
free(data);
printf("%d\n", data[0]);   // ❌ use-after-free
data = NULL;                // 只能防止再通过 data 误用，其他别名仍可能悬空
```

### 5. 重复释放或释放非起始地址

```c
int *data = malloc(4 * sizeof *data);
int *middle = data + 1;

free(middle);          // ❌ free 只能接收分配块的起始地址
free(data);
free(data);            // ❌ 同一分配块不能释放两次
```

### 6. 修改字符串字面量

```c
char *text = "hello";
text[0] = 'H';         // ❌ 修改字符串字面量是未定义行为

char writable[] = "hello";
writable[0] = 'H';     // ✅ 修改自己的字符数组
```

### 7. 有符号整数溢出

```c
int x = INT_MAX;
x = x + 1;             // ❌ 有符号溢出通常是未定义行为

unsigned int y = UINT_MAX;
y = y + 1U;            // ✅ 结果按模 2^N 回到 0
```

### 8. 格式符与实参类型不匹配

```c
size_t length = 10;
printf("%d\n", length);           // ❌ %d 需要 int
printf("%zu\n", length);          // ✅ size_t 使用 %zu

double value;
scanf("%f", &value);               // ❌ scanf 的 %f 需要 float *
scanf("%lf", &value);              // ✅ scanf 的 %lf 需要 double *
```

可变参数函数不会替你检查真实类型。编译警告经常能直接抓住这类错误，所以不要忽略警告。

### 9. 不相关指针做运算

```c
int a[3];
int b[3];
ptrdiff_t distance = &a[2] - &b[0];  // ❌ 不属于同一数组对象
```

指针加减只允许围绕同一数组对象（以及尾后一位）推理；尾后一位可用于比较或结束标记，但不能解引用。

## 四、动态内存的安全模板

### 1. 申请数组前检查乘法溢出

```c
#include <stdint.h>
#include <stdlib.h>

int *make_array(size_t count)
{
    if (count > SIZE_MAX / sizeof(int)) {
        return NULL;                    // count * sizeof(int) 会溢出
    }

    return malloc(count * sizeof(int));
}
```

更推荐让 `sizeof` 跟着指针的目标类型：

```c
int *data = malloc(count * sizeof *data);
```

即使以后把 `data` 改成别的类型，分配表达式也会自动跟着改变。

### 2. `realloc` 必须用临时变量

```c
int *temporary;

temporary = realloc(data, new_count * sizeof *data);
if (temporary == NULL) {
    /*
     * 失败路径：原 data 仍然有效。
     * 如果直接写 data = realloc(...)，失败时原地址会丢失，造成泄漏。
     */
    handle_error();
} else {
    data = temporary;
}
```

> ⚠️ `realloc` 成功后可能搬家，所有指向旧分配块内部的指针都要重新计算。

### 3. 多层分配要逆序回滚

```c
int **rows = calloc(row_count, sizeof *rows);
size_t built = 0;

if (rows == NULL) {
    return NULL;
}

for (built = 0; built < row_count; ++built) {
    rows[built] = malloc(column_count * sizeof *rows[built]);
    if (rows[built] == NULL) {
        while (built > 0) {
            free(rows[--built]);        // 只释放已经成功的行
        }
        free(rows);
        return NULL;
    }
}
```

详见 [[07-指针数组、数组指针与多级指针#八、完整示例一：动态锯齿矩阵与失败回滚|动态锯齿矩阵]]。

## 五、编译器警告先开满

GCC / Clang 的学习期建议：

```bash
cc -std=c11 -Wall -Wextra -Wpedantic -Wconversion -Wshadow \
   -g example.c -o example
```

常见警告的意义：

| 警告 | 经常暴露的问题 |
|---|---|
| incompatible pointer type | 把二维数组、二级指针或错误类型地址混在一起 |
| format | `printf` / `scanf` 格式符和实参类型不匹配 |
| uninitialized | 自动变量或指针没有初始化 |
| conversion | 窄化、符号变化、浮点转整数 |
| shadow | 内层变量遮蔽外层同名变量 |
| return-local-addr | 返回局部自动对象的地址 |

> ✅ 把警告当作编译器替你做的第一次代码审查。学习代码应尽量做到 0 warning，而不是用强制类型转换把警告藏起来。

## 六、用 Sanitizer 抓内存错误

编译器支持时，可以加入：

```bash
cc -std=c11 -Wall -Wextra -Wpedantic -g \
   -fsanitize=address,undefined -fno-omit-frame-pointer \
   example.c -o example
```

- AddressSanitizer：越界、use-after-free、double free 等
- UndefinedBehaviorSanitizer：部分整数溢出、非法移位、对齐错误等

典型定位顺序：

1. 先看报告中的**第一处错误**，后续错误可能只是连锁反应。
2. 找到分配位置、释放位置和出错访问位置。
3. 画出当时仍活着的对象和所有指针别名。
4. 修复所有权或边界，而不是只在崩溃行前加一个 `if`。

## 七、手工调试指针的四列表

遇到复杂代码时，用下面的表逐语句跟踪：

| 表达式 | 自身类型 | 当前值/指向 | 是否仍有效、谁拥有 |
|---|---|---|---|
| `p` | `Node *` | 节点 A 的地址 | 有效，链表拥有 A |
| `&p` | `Node **` | 指针变量 p 的地址 | p 作用域内有效 |
| `p->next` | `Node *` | 节点 B 的地址 | B 未删除时有效 |
| `&p->next` | `Node **` | A 内部 next 槽位的地址 | A 未删除时有效 |

这张表尤其适合分析 [[09-链表与动态内存#四、Node **：统一删除头节点与中间节点|Node 双指针删除]] 和 `qsort` 比较器。

## 八、提交代码前的检查清单

### 数组与字符串

- [ ] 每个下标都能证明在 `[0, length)` 内
- [ ] 作为字符串使用的字符数组一定有 `\0`
- [ ] `scanf("%s", ...)` 有最大宽度，或改用 `fgets`
- [ ] 没有用函数参数里的 `sizeof(arr)` 猜数组长度
- [ ] 没有修改字符串字面量

### 指针与动态内存

- [ ] 每个指针在解引用前都指向仍活着的正确类型对象
- [ ] 每个成功的 `malloc/calloc/realloc` 最终只有一次对应释放
- [ ] `free` 接收的是原始分配块起始地址
- [ ] `realloc` 使用临时变量
- [ ] 部分分配失败能释放已经完成的部分
- [ ] 所有权和借用关系写进函数契约或注释

### 结构体与链表

- [ ] 含指针成员的结构体没有被误当成独立深拷贝
- [ ] 删除节点前先保存需要继续访问的地址
- [ ] 删除头/尾、空表、单节点都测试过
- [ ] 双向链表的 `prev` 与 `next` 成对更新
- [ ] 链表改变后，借用节点地址的索引已重建或作废

## 九、自测题

### 1. 声明阅读

说出三个声明的本质：

```c
int *a[4];
int (*b)[4];
int **c;
```

> 答案：`a` 是含 4 个 `int *` 的数组；`b` 是指向“含 4 个 int 的数组”的指针；`c` 是指向 `int *` 对象的指针。

### 2. 指针槽与目标对象

`int *a[4]` 的四个指针槽连续，能否推出它们指向的四个 `int` 连续？

> 答案：不能。连续的是四个地址值本身；目标可以位于栈、静态区或不同堆块。

### 3. 数组退化

```c
void f(int a[10])
{
    printf("%zu\n", sizeof a);
}
```

打印的是 10 个 `int` 的总大小吗？

> 答案：不是。函数形参中的 `int a[10]` 会调整为 `int *a`，这里得到指针大小；长度必须额外传入。

### 4. 结构体复制

`Student b = a;` 后，若 `Student` 含动态字符串 `char *name`，能否分别销毁 `a` 和 `b`？

> 答案：不能直接这样做。浅拷贝让两者共享同一地址，分别释放会 double free；需要深拷贝或明确只有一个拥有者。

### 5. 链表删除

为什么 `Node **link` 比“保存前驱节点再特判头节点”更统一？

> 答案：`link` 始终指向引用当前节点的那个指针槽，头节点对应 `&head`，中间节点对应 `&prev->next`，同一句 `*link = victim->next` 即可改线。

### 6. `qsort` 层级

排序 `Student *items[]` 时，为什么比较器参数不能直接转成 `Student *`？

> 答案：`qsort` 传入的是数组元素的地址。元素类型为 `Student *`，其地址就是 `Student **` 层级；必须先按“指针槽地址”解释，再解引用得到学生地址。

### 7. 生命周期

函数返回局部数组地址为什么危险？

```c
char *make_name(void)
{
    char name[] = "Robin";
    return name;
}
```

> 答案：`name` 具有自动存储期，函数返回后生命周期结束，返回值立即成为悬空指针。

### 8. 一条完整的内存推理

解释下面每一层的类型：

```c
int value = 7;
int *p = &value;
int **pp = &p;
```

| 表达式 | 类型 | 含义 |
|---|---|---|
| `pp` | `int **` | 指针变量 `p` 的地址 |
| `*pp` | `int *` | `p` 保存的值，即 `value` 的地址 |
| `**pp` | `int` | 地址最终对应的整数 7 |
| `&**pp` | `int *` | 再次取得 `value` 的地址 |
