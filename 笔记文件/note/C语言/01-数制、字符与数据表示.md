# 数制、字符与数据表示

> 同一串二进制位本身没有“正负、字符或整数”的含义；**类型决定程序如何解释这些位**。

---

## 一、二进制、十进制与十六进制

计算机最终保存的是二进制位，但人读长串二进制很吃力，所以程序中经常用十六进制做紧凑表示。

| 进制 | 可用数字 | 每一位的权 | C 中常见写法 |
|---|---|---|---|
| 二进制 | `0`、`1` | $2^n$ | C11 没有标准二进制字面量，常用十六进制代替 |
| 八进制 | `0`~`7` | $8^n$ | `0171` |
| 十进制 | `0`~`9` | $10^n$ | `121` |
| 十六进制 | `0`~`9`、`A`~`F` | $16^n$ | `0x79` |

### 1. 二进制转十六进制

**4 位二进制恰好对应 1 位十六进制**，因为 $2^4=16$。从小数点向两边每 4 位分组，不足 4 位时补零。

原笔记中的例子：

```text
二进制：00000000 00000000 00000001 01110001
四位分组：0000 0000 0000 0000 0000 0001 0111 0001
逐组转换：   0    0    0    0    0    1    7    1
十六进制：0x00000171
```

教材有时写成 `00000171H`，C 源代码中应写成 `0x00000171`。

### 2. 整数与二进制小数

- 整数部分：不断“除 2 取余”，余数从下往上读。
- 小数部分：不断“乘 2 取整”，整数位从上往下读。

例如 $5.625$：

```text
整数：5 = 101₂

0.625 × 2 = 1.25  → 取 1，留下 0.25
0.25  × 2 = 0.5   → 取 0，留下 0.5
0.5   × 2 = 1.0   → 取 1，结束

所以：5.625₁₀ = 101.101₂
```

反向换算时，小数点后各位的权依次是 $2^{-1},2^{-2},2^{-3},\ldots$：

$$0.101_2=1\times2^{-1}+0\times2^{-2}+1\times2^{-3}=0.625$$

> ⚠️ 并非所有十进制小数都能用有限二进制表示。例如 `0.1` 的二进制是无限循环小数，因此浮点计算里常见 `0.1 + 0.2` 不能精确等于 `0.3`。这不是 C 算错，而是表示能力有限。

## 二、位模式、字节与类型

C 标准规定 `sizeof(char) == 1`，也就是一个 C 字节；一个字节有多少位由 `CHAR_BIT` 给出。主流电脑上通常是 8 位，但可移植代码不要把这个事实当成语言永远保证的规则。

```c
#include <limits.h>
#include <stdio.h>

int main(void)
{
    printf("每字节位数：%d\n", CHAR_BIT);
    printf("unsigned char：0 ~ %u\n", (unsigned int)UCHAR_MAX);
    printf("signed char：%d ~ %d\n", SCHAR_MIN, SCHAR_MAX);
    return 0;
}
```

同一个 8 位模式 `10000001` 可以有不同解释：

```text
10000001
│      │
│      └─ 作为无符号整数：129
├──────── 作为常见二进制补码 signed char：-127
└──────── 作为字符编码：取决于执行字符集，未必是可打印字符
```

所以要分清两个问题：

1. **内存里有哪些位？** 这是对象表示。
2. **表达式把它当什么类型使用？** 这决定数值、运算规则和输出方式。

需要明确位宽时，可以使用 `<stdint.h>` 中的 `uint8_t`、`uint16_t`、`uint32_t` 等类型；这些精确宽度类型只在平台支持时才会提供。

## 三、有符号数、无符号数与补码

### 1. 无符号整数

一个 $N$ 位无符号整数的范围是 $0$ 到 $2^N-1$。无符号运算按模 $2^N$ 进行，因此回绕是语言明确规定的：

```c
unsigned char x = UCHAR_MAX;
x = (unsigned char)(x + 1u);  // 明确定义：回到 0
```

### 2. 常见二进制补码

原码、反码和补码是不同概念。以常见的 8 位二进制补码表示 `-5`：

```text
+5：00000101
逐位取反：11111010   ← 反码步骤
再加 1： 11111011   ← -5 的补码位模式
```

补码求值也可以看成：最高位权重为 $-2^7$，其余位权重仍为正：

$$11111011_2=-128+64+32+16+8+2+1=-5$$

> 原笔记把“负数符号位不变、其余取反”称为反码，这是讲**原码转反码**的规则，不是现代机器最终保存负整数的一般步骤。做实际 C 程序时应重点理解补码；也不要把一个 32 位对象任意拆成四个“8 位有符号数”分别判断。

### 3. 不要把所有溢出都理解成“循环”

| 情况 | C 语言规则 |
|---|---|
| 无符号整数运算超范围 | 按模 $2^N$ 回绕，行为有定义 |
| 有符号整数运算溢出 | **未定义行为**，不能依赖它回绕 |
| 超范围整数转成有符号类型 | 结果由实现定义，不能写成可移植逻辑 |

## 四、`char` 的本质与三种字符类型

`char` 是最小的整数类型，适合保存字符编码单元或原始字节。三种写法含义不同：

| 类型 | 常见 8 位范围 | 重点 |
|---|---:|---|
| `signed char` | -128 ~ 127 | 明确是有符号小整数 |
| `unsigned char` | 0 ~ 255 | 适合查看对象的原始字节 |
| `char` | 取决于编译器 | 是独立类型，带不带符号由实现决定 |

原笔记说“普通 `char` 默认就是 `signed char`”并不具备可移植性。若算法依赖正负范围，应明确写 `signed char` 或 `unsigned char`。

### 1. 字符实际保存的是编码值

在常见 ASCII 环境里：`'A'` 是 65、`'a'` 是 97、`'0'` 是 48、空格是 32。

```c
char c = 'a';
printf("%c\n", c);       // 按字符显示：a
printf("%d\n", (int)c);  // 按整数显示：常见 ASCII 环境下为 97
```

C 标准保证数字字符 `'0'` 到 `'9'` 的编码连续，所以字符数字与整数之间可以安全换算：

```c
int digit = '7' - '0';  // 7
char text = (char)(3 + '0');  // '3'
```

但“大小写固定相差 32”是 **ASCII 特性，不是 C 语言保证**。通用程序应使用 `<ctype.h>`：

```c
#include <ctype.h>

unsigned char raw = (unsigned char)c;
char upper = (char)toupper(raw);  // ctype 参数应先转成 unsigned char，避免负 char 导致未定义行为
```

### 2. 字符常量与字符串字面量

- `'A'` 是字符常量；在 C 中它的类型是 `int`，值能转换为 `char`。
- `"A"` 是包含 `'A'` 和结尾 `\0` 的字符数组字面量。
- `'ab'` 不是两个字符组成的字符串，而是实现定义的多字符常量；不要依赖它。

## 五、转义字符与 `\0`

反斜杠把不方便直接书写的字符变成一个转义序列：

| 写法 | 含义 |
|---|---|
| `\n` | 换行 |
| `\t` | 水平制表 |
| `\'`、`\"` | 单引号、双引号 |
| `\\` | 反斜杠 |
| `\0` | 值为 0 的空字符，常作字符串结束标志 |

### 数字转义的两个易错点

- 八进制转义是反斜杠后 **1~3 个**八进制数字，而不是必须 3 位。`"\348"` 会被拆成 `\34` 与普通字符 `'8'`，因为 `8` 不是八进制数字。
- 十六进制转义 `\x` 后会持续读取十六进制数字，**并不固定为两位**。若后面紧跟 `A`~`F` 等字符，应拆开字符串避免被吞进去，例如 `"\x41" "B"`。

字符串函数依靠第一个 `\0` 判断终点：

```c
char text[] = "abc\n\34" "8\0china";
```

从开头到显式 `\0` 之前依次是 `a b c \n \34 8`，所以 `strlen(text)` 为 6；但数组仍为后面的 `china` 和最终自动补上的 `\0` 分配空间。`sizeof(text)` 得到整个数组字节数，二者不要混淆。详见 [[05-数组、字符串与内存布局]]。

## 六、整数提升：为什么 `char` 运算后常变成 `int`

`char` 和 `short` 参与大多数算术运算时，会先进行**整数提升**，通常提升成 `int`：

```c
char a = 'A';
int result = a + 1;       // 先把 a 提升为 int，再相加
printf("%c\n", result);  // 常见 ASCII 环境输出 B；%c 接收的是提升后的 int
```

这解释了字符为什么能加减，也解释了可变参数函数中的类型匹配：传给 `printf` 的 `char` 会提升为 `int`，但格式符仍必须与规定类型对应。详见 [[02-输入输出与字符处理]]。

## 七、综合示例：把十六进制文本解析成 32 位整数

这个例子把“字符编码、进制、整数范围和位运算”连在一起。输入可带 `0x`，遇到非法字符或超过 `uint32_t` 范围时拒绝结果。

```c
#include <inttypes.h>
#include <stdint.h>
#include <stdio.h>

static int hex_digit_value(char c)
{
    if (c >= '0' && c <= '9') {
        return c - '0';  // C 保证十进制数字字符连续
    }
    switch (c) {
        // 难点：C 只保证数字字符连续，不保证所有字母编码连续；逐项列出最可移植。
        case 'a': case 'A': return 10;
        case 'b': case 'B': return 11;
        case 'c': case 'C': return 12;
        case 'd': case 'D': return 13;
        case 'e': case 'E': return 14;
        case 'f': case 'F': return 15;
        default: return -1;
    }
}

static int parse_hex_u32(const char *text, uint32_t *out)
{
    uint32_t value = 0;
    size_t i = 0;

    if (text == NULL || out == NULL) {
        return 0;  // 边界：空指针不能解引用
    }
    if (text[0] == '0' && (text[1] == 'x' || text[1] == 'X')) {
        i = 2;  // 跳过可选前缀
    }
    if (text[i] == '\0') {
        return 0;  // 边界：只有“0x”而没有数字
    }

    for (; text[i] != '\0'; ++i) {
        int digit = hex_digit_value(text[i]);
        if (digit < 0) {
            return 0;  // 非十六进制字符
        }

        // 难点：执行 value * 16 + digit 前先判断是否会超过 UINT32_MAX。
        if (value > (UINT32_MAX - (uint32_t)digit) / 16u) {
            return 0;
        }
        value = value * 16u + (uint32_t)digit;
    }

    *out = value;  // 只有完整解析成功后才修改调用者的结果
    return 1;
}

int main(void)
{
    const char input[] = "0x00000171";
    uint32_t value = 0;

    if (!parse_hex_u32(input, &value)) {
        fprintf(stderr, "不是合法的 32 位十六进制数\n");
        return 1;
    }

    printf("十进制：%" PRIu32 "\n", value);
    printf("十六进制：0x%08" PRIX32 "\n", value);
    return 0;
}
```

预期输出：

```text
十进制：369
十六进制：0x00000171
```

## 八、易错点速查

1. `0x171` 是 C 的十六进制写法，`171H` 不是标准 C 字面量。
2. 普通 `char` 的有符号性由实现决定，不要默认范围一定是 -128~127。
3. 无符号回绕有定义；有符号溢出是未定义行为。
4. `'0'` 是字符编码值，`0` 是整数零，`'\0'` 的数值也等于零但语义常作字符串终点。
5. `\ddd` 最多读取 3 个八进制数字；`\x...` 会一直读取十六进制数字。
6. 大小写相差 32 只适用于 ASCII 等兼容编码，通用代码用 `toupper`/`tolower`。
7. 位模式与数值不是一回事：先确定类型，再谈这串位代表什么。
