# 函数、作用域与生命周期

> 函数调用会创建一组新的参数和局部对象；**作用域决定名字在哪里可见，存储期决定对象活多久**，两者不能混为一谈。

---

## 一、函数的声明、定义与调用

函数把一段职责明确的代码命名起来。完整流程包含三部分：

```text
函数声明（原型） ──→ 编译器知道接口
函数定义          ──→ 提供真正的实现
函数调用          ──→ 传入实参并接收结果
```

```c
#include <stdio.h>

int add(int left, int right);  // 1. 声明：返回 int，接收两个 int

int main(void)
{
    int sum = add(3, 5);       // 3. 调用：3、5 是实参
    printf("%d\n", sum);
    return 0;
}

int add(int left, int right)   // 2. 定义：left、right 是形参
{
    return left + right;
}
```

### 函数原型为什么重要

原型让编译器在调用处检查参数数量、类型与返回类型。函数定义写在调用之前时，定义本身也提供原型；定义写在 `main` 后面时，应先声明。

> ⚠️ 在 C11 中，`void say(void)` 表示明确不接收参数；`void say()` 是旧式写法，表示参数信息未指定。无参数函数应写 `(void)`，不要省略。

### 常见接口形状

```c
void say(void);                    // 无参数、无返回值
void print_number(int value);      // 有参数、无返回值
int add(int left, int right);      // 有参数、有返回值
int read_value(int *out_value);    // 返回状态，通过指针输出另一个结果
```

`void` 返回类型表示函数不产生可供表达式使用的结果；非 `void` 函数应在所有正常路径上返回与声明兼容的值。

## 二、一次函数调用发生了什么

概念上，每次调用都会获得自己的一份形参和自动局部对象：

```text
main 的调用现场
┌────────────────────────────┐
│ a = 3, b = 5               │
│ 下一步：接收 add 的返回值   │
└──────────────┬─────────────┘
               │ 调用 add(a, b)
               ▼
add 的本次调用
┌────────────────────────────┐
│ left = 3   ← a 的值的副本   │
│ right = 5  ← b 的值的副本   │
│ result = 8                 │
└──────────────┬─────────────┘
               │ return 8
               ▼
回到 main 的调用点继续执行
```

实际实现通常使用调用栈、寄存器和调用约定共同完成参数传递与返回，但 C 语言层面最重要的规则是：**参数按值传递**。

### `return` 的两层作用

1. 立即结束当前函数，后面的语句不再执行。
2. 对非 `void` 函数，把一个值交回调用表达式。

```c
int absolute_value(int x)
{
    if (x >= 0) {
        return x;   // 当前函数到此结束
    }
    return -x;
}
```

这里若 `x == INT_MIN`，`-x` 可能导致有符号溢出，因此真正的通用绝对值还要考虑类型边界。详见 [[11-未定义行为、调试与自测]]。

## 三、C 永远是值传递，指针传参也不例外

### 1. 普通参数：修改副本不影响实参

```c
void bad_swap(int x, int y)
{
    int temp = x;
    x = y;
    y = temp;  // 只交换本次调用中的两个副本
}
```

### 2. 指针参数：地址值也被复制，但能沿地址修改对象

```c
void swap(int *left, int *right)
{
    int temp = *left;  // 沿复制进来的地址访问调用者对象
    *left = *right;
    *right = temp;
}

int main(void)
{
    int a = 1;
    int b = 2;

    swap(&a, &b);      // 把 a、b 的地址值复制给形参
    printf("a=%d, b=%d\n", a, b);
    return 0;
}
```

所以原笔记中的“值传递 vs 地址传递”更准确的表达是：

- C 的参数**全部按值复制**。
- 传普通值时，函数只能修改副本。
- 传指针值时，函数可以解引用，修改指针所指的原对象。

若指针参数允许为空，函数应先检查；若绝不允许为空，应在接口说明中明确。指针本身、解引用与所有权详见 [[06-指针与C内存模型]]。

## 四、作用域：这个名字在哪里能被查到

### 1. 块作用域

在函数体或任意 `{}` 中声明的名字，从声明位置开始到当前块结束可见：

```c
void example(void)
{
    int outer = 10;

    {
        int inner = outer + 1;  // inner 只在这个内层块可见
        printf("%d\n", inner);
    }

    /* 此处不能再使用 inner */
}
```

函数形参也具有函数定义中的块作用域。

### 2. 文件作用域

所有函数之外声明的名字从声明位置到当前源文件结尾可见：

```c
static int error_count;  // 文件作用域；static 还让名字只在本源文件链接

void report_error(void)
{
    ++error_count;
}
```

原笔记说“全局变量整个程序所有函数都能用”过于绝对。一个文件作用域对象在别的 `.c` 文件中能否使用，还取决于**链接属性**以及是否有可见的 `extern` 声明。

### 3. 遮蔽与就近查找

```c
int value = 100;  // 文件作用域

int main(void)
{
    int value = 10;       // 遮蔽外层同名对象
    printf("%d\n", value);  // 输出 10
    return 0;
}
```

遮蔽合法，但容易误读。比起依赖“就近原则”，更好的做法是给不同职责的对象使用不同名字，并开启 `-Wshadow` 检查。

## 五、存储期：对象从什么时候存在到什么时候

“生命周期”是日常说法，C 标准更精确的术语是**存储期**。

| 存储期 | 常见对象 | 创建与结束 | 未显式初始化 |
|---|---|---|---|
| 自动存储期 | 普通局部变量、形参 | 每次进入所属块时创建，离开时结束 | 值不确定，读取可能是未定义行为 |
| 静态存储期 | 文件作用域对象、`static` 局部对象 | 程序运行期间一直存在 | 零初始化 |
| 分配存储期 | `malloc` 等得到的对象 | 成功分配后开始，`free` 时结束 | 内容不确定（`calloc` 除外） |
| 线程存储期 | `_Thread_local` 对象 | 所属线程执行期间 | 零初始化 |

### 1. 自动局部对象

```c
void f(void)
{
    int x;       // 自动存储期，值不确定
    int y = 0;   // 明确初始化
    /* printf("%d", x); 读取未初始化的 x 可能是未定义行为 */
}
```

“未初始化局部变量是随机垃圾数”只能作直觉提醒，不能当作可读取的某个随机值；标准层面应视为**不能使用**。

### 2. 静态局部对象

```c
void visit(void)
{
    static unsigned count;  // 静态存储期，程序启动时零初始化
    ++count;
    printf("第 %u 次调用\n", count);
}
```

`count` 的名字仍只有块作用域，但对象从程序开始到结束一直存在，每次调用都会保留上一次结果。它不是每次进入函数时重新初始化。

### 3. 动态分配对象

```c
int *p = malloc(sizeof *p);
if (p != NULL) {
    *p = 42;
    free(p);      // free 后对象的存储期结束
    p = NULL;     // 避免继续保留一个容易误用的悬空值
}
```

动态对象不受创建它的函数块限制，但必须由程序明确释放。详见 [[09-链表与动态内存]]。

## 六、典型内存区域与存储期的关系

在常见桌面系统中，可以用下面的实现模型帮助理解，但 C 标准并没有强制变量必须放在这些具体区域：

```text
较高地址（示意）
┌──────────────────────────┐
│ 调用栈：自动局部对象、形参 │ ← 函数返回后对应调用现场失效
├──────────────────────────┤
│          空闲区域          │
├──────────────────────────┤
│ 堆：malloc/calloc/realloc │ ← 直到 free，或进程结束
├──────────────────────────┤
│ 全局/静态数据             │ ← 静态存储期
├──────────────────────────┤
│ 只读数据、字符串字面量     │ ← 通常不可修改
├──────────────────────────┤
│ 程序机器指令              │
└──────────────────────────┘
较低地址（示意）
```

### 绝不能返回自动局部对象的地址

```c
int *wrong(void)
{
    int local = 42;
    return &local;  // 错误：函数返回后 local 的存储期结束
}
```

返回后，这个地址不再指向一个仍存活的 `int` 对象，继续解引用属于未定义行为。可以改为：

- 返回对象的值；
- 由调用者提供输出地址；
- 返回静态对象地址，但要接受共享状态和不可重入等限制；
- 动态分配并明确把释放责任交给调用者。

## 七、`static` 与 `extern`：位置不同，含义不同

### 1. 块内 `static`

改变对象的存储期：名字只在块内可见，对象却在程序全程存在并保留状态。

### 2. 文件作用域 `static`

改变名字的链接属性，使函数或对象只在当前 `.c` 文件中可用：

```c
static int clamp(int value, int low, int high)
{
    if (value < low) {
        return low;
    }
    if (value > high) {
        return high;
    }
    return value;
}
```

这是实现文件中“私有辅助函数”的常见写法。

### 3. `extern` 声明

跨源文件共享对象时，通常在一个 `.c` 文件中给出唯一定义，在头文件中给出 `extern` 声明：

```c
/* counter.h */
extern unsigned long event_count;

/* counter.c */
unsigned long event_count = 0;  // 唯一定义，实际提供对象
```

全局可变状态会增加模块耦合，应优先通过函数接口管理；确需共享时再使用。

## 八、函数不能嵌套定义，但可以嵌套调用

标准 C 不允许在一个函数体内部定义另一个函数：

```c
void outer(void)
{
    /* void inner(void) { }  标准 C 不允许 */
}
```

但函数 A 调用函数 B 完全合法，函数也可以调用自己，这就是递归：

```c
unsigned long long factorial(unsigned int n)
{
    if (n <= 1u) {
        return 1u;  // 递归终止条件
    }
    return n * factorial(n - 1u);
}
```

每一层递归调用都有独立的形参 `n` 和返回位置。必须有可到达的终止条件，还要留意调用深度和乘法溢出。

## 九、综合示例：用静态局部状态计算运行平均值

这个程序融合函数原型、值传递、指针输出、`static` 局部对象和返回状态。为了突出生命周期，状态保存在函数内部；若要同时维护多组统计，应改用结构体对象，而不是继续增加隐藏的静态状态。详见 [[08-结构体、内存对齐与所有权]]。

```c
#include <stddef.h>
#include <stdio.h>

/* reset 非零时清空历史；正常加入 sample 后，通过 out_average 返回均值。 */
static int running_average(double sample, int reset, double *out_average)
{
    static double sum;    // 静态存储期：跨调用保留；未显式初始化也会从 0 开始
    static size_t count;  // 块作用域：只有本函数能直接访问这个名字

    if (reset) {
        sum = 0.0;
        count = 0;
        return 1;
    }
    if (out_average == NULL) {
        return 0;  // 边界：不能通过空指针写结果
    }

    sum += sample;
    ++count;
    *out_average = sum / (double)count;  // 难点：沿地址修改调用者的 average 对象
    return 1;
}

int main(void)
{
    const double samples[] = {10.0, 14.0, 18.0, 22.0};
    const size_t count = sizeof samples / sizeof samples[0];
    double average = 0.0;

    if (!running_average(0.0, 1, NULL)) {
        return 1;
    }

    for (size_t i = 0; i < count; ++i) {
        if (!running_average(samples[i], 0, &average)) {
            fprintf(stderr, "无法计算平均值\n");
            return 1;
        }
        printf("加入 %.1f 后，平均值 = %.2f\n", samples[i], average);
    }

    return 0;
}
```

预期输出：

```text
加入 10.0 后，平均值 = 10.00
加入 14.0 后，平均值 = 12.00
加入 18.0 后，平均值 = 14.00
加入 22.0 后，平均值 = 16.00
```

这个设计有意暴露了静态局部状态的限制：

1. 状态只有一份，无法同时计算两组独立平均值。
2. 调用顺序会影响结果，测试前必须重置。
3. 多线程同时调用还会产生共享状态问题。

因此 `static` 适合简单计数器或模块私有状态；可复用对象更适合由调用者持有结构体，并把它的地址传给函数。

## 十、易错点速查

1. 无参数原型写 `function(void)`，不要在 C11 中用 `function()` 表示“无参数”。
2. 函数在调用点之前没有可见声明，会失去类型检查并违反现代 C 约束。
3. C 所有参数都按值传递；指针参数只是复制地址值后再间接访问对象。
4. 自动局部变量未初始化时值不确定，读取它不是“得到随机数”，而可能是未定义行为。
5. 文件作用域对象默认零初始化，但是否能跨 `.c` 文件使用取决于链接与声明。
6. 静态局部对象的作用域仍在块内，只是存储期延长到程序全程。
7. 不要返回自动局部对象地址；函数结束后对象已经不存在。
8. `return` 只结束当前函数；递归必须有终止条件并考虑深度与溢出。
9. 标准 C 不支持嵌套定义函数；某些编译器扩展能编译，不代表可移植。
