## 怎样读 `ls -l`

```text
-rwxr-x---  1 student developers 1234 Sep 3 12:00 app
│└─┬─┘└┬┘└┬┘
类型 属主 属组 其他人
```

第一个字符常见：`-` 普通文件、`d` 目录、`l` 符号链接。后九位分别为属主、属组和其他人的 `rwx` 权限。

## 文件和目录里的 rwx 含义不同

| 权限 | 普通文件 | 目录 |
|---|---|---|
| `r` | 读取内容 | 列出目录项名字 |
| `w` | 修改内容 | 创建、删除、重命名目录项，通常还需 `x` |
| `x` | 允许执行 | 搜索/穿过目录、访问已知路径 |

能否删除文件主要受父目录权限影响，不等于文件本身是否可写；sticky bit、ACL、只读挂载等也会影响结果。参见 [GNU 权限说明](https://www.gnu.org/software/coreutils/manual/html_node/Setting-Permissions.html)。

## chmod 数字记法

```text
r = 4，w = 2，x = 1
7 = rwx，6 = rw-，5 = r-x，4 = r--，0 = ---
```

```bash
chmod u+x ./run.sh          # 给属主增加执行权限
chmod 644 ./notes.txt       # 属主读写，其他人只读
chmod 750 ./run.sh          # 属主 rwx，属组 r-x，其他人无权限
chmod 700 ./private-dir    # 私有目录
```

不要用 `chmod 777` 作为通用修复；它可能把配置、代码或数据交给所有本机用户修改。`chmod -R`、`chown -R` 会影响整棵目录树，操作前必须检查范围。

## 属主、用户组和 sudo

```bash
id
groups
ls -ld ./project
```

```bash
# 修改属主的示意：仅对确认属于该用户的目录使用
sudo chown student:developers /srv/my-project
```

`sudo` 允许经授权的用户以另一身份执行命令，默认通常是 root。它不是“让错误消失”的魔法：路径错误、文件系统只读、程序配置错误都不该靠提权掩盖。

`umask` 控制创建文件时屏蔽哪些默认权限，不会修改已有文件。常见 `022` 通常使普通新文件为 644、目录为 755，但还取决于程序请求的权限和 ACL。

> [!note] 进阶再学
> sticky bit 常用于共享临时目录；setgid 可影响共享目录中新文件的属组；setuid 涉及提权风险，不要随意给程序设置。
