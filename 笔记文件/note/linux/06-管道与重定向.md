## 标准输入、输出、错误

```text
stdin  = 0：标准输入，默认键盘
stdout = 1：标准输出，默认终端
stderr = 2：标准错误，默认终端
```

```bash
./app > output.log             # 覆盖标准输出文件，stderr 仍显示在终端
./app >> output.log            # 追加标准输出
./app 2> error.log             # 单独保存标准错误
./app > all.log 2>&1           # 先重定向 stdout，再让 stderr 指向同一去处
./app < input.txt              # 从文件读取标准输入
```

重定向由 Shell 处理，而且有顺序：`2>&1 >out.log` 与 `>out.log 2>&1` 不等价。`>` 可能在程序开始前就截断目标文件。参见 [Bash 重定向手册](https://www.gnu.org/s/bash/manual/html_node/Redirections.html)。

## 管道连接数据，不是拼接文件名

```bash
grep 'ERROR' ./app.log | wc -l
```

```text
grep 读取文件 → 匹配行写到 stdout → 管道 → wc 从 stdin 计数
```

默认 `|` 只传标准输出；Bash 的 `|&` 可同时传标准输出与错误。管道不会把前一个程序的所有内部状态交给后一个程序。参见 [Bash 管道手册](https://www.gnu.org/software/bash/manual/html_node/Pipelines)。

## 常见文本处理组合

```bash
sort names.txt | uniq -c | sort -nr  # 先排序，使相同项相邻，再统计频次
cut -d ',' -f 1 simple.csv           # 仅适合没有复杂引号的简单分隔文本
sed -n '10,20p' app.log              # 打印指定行，不修改原文件
awk '{print $1, $3}' data.txt        # 默认按空白分列
./app 2>&1 | tee run.log            # 屏幕显示并保存；会覆盖 run.log
```

`uniq` 只合并相邻重复行，不会自动找出整个文件中所有重复值。复杂 CSV 应交给真正的 CSV 解析器，不要用 `cut` 硬拆。

> [!warning] 不要一边读取一边截断
> `sort data.txt > data.txt` 会让 Shell 先清空输入文件。应输出到另一个文件，验证后再替换。
