本节针对使用 systemd 的系统；容器、某些 WSL 环境或精简发行版未必适用。先确认 PID 1：

```bash
ps -p 1 -o comm=
```

## 先看状态和日志，再做修改

```bash
systemctl status myapp.service
systemctl is-active myapp.service
systemctl is-enabled myapp.service
systemctl --failed
journalctl -u myapp.service -n 100 --no-pager
journalctl -u myapp.service -f
journalctl -b -p warning
```

`-u` 按单元筛选，`-f` 跟踪新日志，`-b` 看本次启动；访问部分系统日志可能需要授权。参见 [systemd 日志手册](https://www.freedesktop.org/software/systemd/man/255/journalctl.html)。

## 启动、开机启动不是一件事

| 命令 | 含义 |
|---|---|
| `sudo systemctl start myapp.service` | 现在启动 |
| `sudo systemctl stop myapp.service` | 现在停止 |
| `sudo systemctl restart myapp.service` | 重启，可能中断连接 |
| `sudo systemctl enable myapp.service` | 按单元安装规则启用，例如加入启动依赖 |
| `sudo systemctl enable --now myapp.service` | 启用并立即启动 |
| `sudo systemctl disable myapp.service` | 取消启用，通常不立即停止 |

这些操作的差异可查 [systemctl 官方手册源文件](https://github.com/systemd/systemd/blob/main/man/systemctl.xml)。不要为了排错直接重启整台机器；先记录错误日志。

修改 unit 文件后通常执行 `systemctl daemon-reload` 让管理器重新读取定义；这不等于应用已经加载新配置。应用是否支持 `reload` 也要查自己的文档。
