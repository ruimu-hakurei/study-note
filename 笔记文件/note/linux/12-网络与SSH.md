## 用分层方式排查网络

```text
网卡与地址 → 路由 → DNS → 传输层端口 → 应用协议 → 权限/业务逻辑
```

```bash
ip -br addr                    # 网卡与 IP
ip route                       # 路由，特别是默认路由
ss -lnt                        # 查看监听的 TCP 端口
ss -lntp                       # 尝试显示监听进程，部分信息可能需权限
getent hosts example.com        # 使用系统名称解析机制
ping -c 4 example.com           # ICMP 探测；不通不等于 HTTP 一定不通
curl -I --max-time 10 https://example.com
```

`curl -I` 发 HEAD 请求，某些服务不支持 HEAD，不能只凭这一项判断服务是否正常。需要查看响应体时可用普通 GET 请求，注意不要把含凭证的 URL 或响应泄露到日志中。

## 监听地址决定从哪里能访问

| 监听地址 | 含义 |
|---|---|
| `127.0.0.1` | IPv4 本机回环，只能从本机访问 |
| `0.0.0.0` | 所有本机 IPv4 接口，不是浏览器里应填写的目标地址 |
| 某个网卡 IP | 仅绑定该地址 |
| `::1` / `::` | IPv6 回环 / 通配地址；是否同时接收 IPv4 取决于配置 |

端口监听正确仍可能被防火墙、路由、容器端口映射或云侧访问策略限制。不要为排错直接关闭所有防火墙。

## SSH 远程登录

```bash
ssh student@server.example.com
ssh -p 2222 student@server.example.com    # 服务器 SSH 端口不是默认值时
exit                                    # 退出远程会话
```

SSH 提供加密远程连接。首次连接的主机密钥指纹应通过可信渠道核对，不要机械接受未知指纹；原主机指纹突然变化也不能直接忽略。

```bash
scp ./app student@server.example.com:/home/student/uploads/
```

复制前确认远端目录和覆盖风险。使用密钥登录时，公钥可放到服务器授权列表，私钥要保留在本机并妥善保护，不能上传到公开仓库或发给别人。

## 网络报错怎样理解

| 报错/现象 | 优先检查 |
|---|---|
| `Could not resolve host` | DNS、域名拼写、解析配置 |
| `Connection refused` | 目标端口未监听或被明确拒绝 |
| 连接超时 | 网络路径、防火墙、地址错误、服务无响应 |
| HTTP 401 / 403 | 已有 HTTP 响应，转查身份认证/访问权限 |
| HTTP 500 | 服务端应用错误，查看应用日志 |

这些是排查方向，不是单凭一句报错就能确定根因。
