## 本地、低风险实验

确认安装 Python 3，创建一个专门提供测试文件的空目录，不要用含密码或私有资料的目录。终端 A：

```bash
mkdir -p ~/linux-lab/web-demo
cd ~/linux-lab/web-demo
python3 -m http.server 8080 --bind 127.0.0.1
```

只绑定本机回环，其他机器不能直接访问。终端 B：

```bash
curl -I --max-time 3 http://127.0.0.1:8080/
ss -lntp 'sport = :8080'
```

回到终端 A 用 Ctrl+C 结束自己启动的服务。这个开发服务器仅用于实验，不是面向公网的生产部署方案。

## 按证据逐层排查

| 检查步骤 | 观察什么 | 下一步 |
|---|---|---|
| 进程是否存在 | 前台终端输出、`ps`、服务状态 | 退出则先看错误日志 |
| 是否监听 | `ss -lntp` | 地址和端口是否正确 |
| 本机请求 | `curl` 访问回环/绑定地址 | 先证实应用本身可达 |
| 局域网请求 | 使用服务器实际 IP | 检查是否只绑定回环 |
| 网络策略 | 防火墙、容器映射等 | 只调整必要规则，保留管理连接 |
| 应用响应 | HTTP 状态和服务日志 | 处理认证、路径或业务错误 |

若 8080 已被占用，不要直接杀死占用者。先查 PID、命令行和用途，实验时也可以换一个未占用端口。

## 扩展：systemd 用户服务的结构

在支持 systemd 用户服务的 Linux 中，可用编辑器创建 `~/.config/systemd/user/web-demo.service`。这只是同一个本地实验的管理方式；创建前检查是否有同名文件：

```ini
[Unit]
Description=Local Linux learning HTTP server

[Service]
Type=simple
WorkingDirectory=%h/linux-lab/web-demo
# 先用 command -v python3 确认本机解释器路径；此处是常见路径示例。
ExecStart=/usr/bin/python3 -m http.server 8080 --bind 127.0.0.1
Restart=on-failure
RestartSec=3

[Install]
WantedBy=default.target
```

先停止终端 A 的服务器，避免端口冲突，再在自己的用户会话内操作：

```bash
systemctl --user daemon-reload
systemctl --user start web-demo.service
systemctl --user status web-demo.service
journalctl --user -u web-demo.service -n 30 --no-pager
systemctl --user stop web-demo.service
```

此处不默认设置开机启动。用户服务是否随登录启动、退出会话后是否继续，取决于用户管理器和 linger 等设置，不应直接当作系统级服务。
