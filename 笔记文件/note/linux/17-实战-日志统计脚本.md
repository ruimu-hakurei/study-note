## 目标与输入约定

项目位于 `~/linux-lab`。假设 `app.log` 每行固定为：**时间、级别、剩余消息**，以空白分隔，例如：

```text
2026-09-03T10:00:00 INFO started
2026-09-03T10:00:01 WARN sensor timeout
2026-09-03T10:00:02 ERROR read failed
2026-09-03T10:00:03 INFO retry succeeded
```

希望统计 INFO/WARN/ERROR 行数，不修改原日志。用编辑器创建 `log_summary.sh`：

```bash
#!/usr/bin/env bash
set -euo pipefail

if [[ $# -ne 1 ]]; then
    printf '用法：%s 日志文件\n' "$0" >&2
    exit 2
fi

log_file="$1"
if [[ ! -f "$log_file" || ! -r "$log_file" ]]; then
    printf '无法读取普通文件：%s\n' "$log_file" >&2
    exit 1
fi

# 用输入重定向把文件交给 awk：路径中的空格或前导 - 不会变成 awk 选项。
# 级别固定在第二列，只数合法级别；空行跳过，格式异常的行单独记录。
awk '
    NF == 0 { next }
    NF < 3  { invalid++; next }
    $2 == "INFO"  { info++; next }
    $2 == "WARN"  { warn++; next }
    $2 == "ERROR" { error++; next }
    { invalid++ }
    END {
        printf "INFO=%d\nWARN=%d\nERROR=%d\nINVALID=%d\n", \
               info, warn, error, invalid
    }
' < "$log_file"
```

```bash
bash -n ./log_summary.sh
bash ./log_summary.sh ./app.log
bash ./log_summary.sh ./app.log > ./summary.txt
```

预期：`INFO=2`、`WARN=1`、`ERROR=1`、`INVALID=0`。`summary.txt` 是新报告；再次使用 `>` 会覆盖它。

## 这个项目练到了什么

```text
参数检查 → 文件权限检查 → 引号保护路径 → stdin 输入 → awk 按列统计
                                                        ↓
                                                stdout 输出报告
                                                        ↓
                                                Shell 重定向保存
```

没有用“消息里包含 ERROR”判断级别，因为普通消息也可能谈到 ERROR。真实 JSON 日志应用 `jq` 等结构化解析工具，不要强行套用这个固定列格式。

## 自测

- [ ] 没有传参数时退出码是 2。
- [ ] 不存在的文件不会被创建。
- [ ] 文件名含空格仍能读取。
- [ ] 空文件返回四个零。
- [ ] 未知级别和格式不完整的行计入 INVALID。
