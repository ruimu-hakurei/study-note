## 本机编译和交叉编译

```text
在 x86_64 Linux 编译并运行 x86_64 程序 → 本机编译
在 x86_64 Linux 生成 ARM Linux 程序   → 交叉编译
在 Linux 生成 STM32 裸机固件         → 裸机交叉编译
```

`arm-none-eabi-gcc` 面向相应裸机目标；ARM Linux 工具链还需匹配用户态 ABI、C 库和 sysroot。不能因为“都是 ARM”就互换可执行文件。

```bash
file ./app
uname -m
```

遇到 `Exec format error`，先查体系结构和文件格式。文件明明存在却提示加载失败，还可能缺少 ELF 解释器/动态加载器，而非路径真的不存在。

## 串口与设备节点

```bash
ls -l /dev/ttyUSB0
id
journalctl -k -n 50 --no-pager
```

设备可能叫 `/dev/ttyUSB0`、`/dev/ttyACM0` 等，编号可因插拔改变。设备节点的属组和权限决定普通用户能否打开它；应检查本机实际规则，不要通过永久 `chmod 777` 解决。

某些系统用 `dialout` 组控制串口访问，其他系统可能不同。调整用户组需要管理员授权，通常还要重新登录才在新会话生效。稳定设备命名可以继续学习 udev 规则。

## 后续进阶路线

```text
Shell 与文件权限
    ↓
C 编译、调试、Make/CMake
    ↓
进程/线程、文件 I/O、IPC、Socket
    ↓
交叉编译与 sysroot
    ↓
设备树、驱动、Buildroot/Yocto、嵌入式系统构建
```

Linux 用户态开发和内核驱动开发是两层工作，先掌握用户态程序与系统调用，再进入驱动更容易理解。
